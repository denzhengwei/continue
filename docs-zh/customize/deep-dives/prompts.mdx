提示词作为用户消息包含在内，特别适用于重复性和/或复杂任务的指令。

## 斜杠命令

通过将 `invokable` 设置为 `true`，您可以将 Markdown 文件设为提示词，当您在聊天、计划和代理模式下键入 <kbd>/</kbd> 时，该提示词将可用。

```md title="explain-invokable.md"
---
name: Explain invokable
description: Explains what happens when you set invokable to true
invokable: true
---

Explain that when `invokable` is set to `true`, a slash command becomes available in the IDE extensions and CLI
```

这些斜杠命令可以与其他指令（包括高亮代码）结合使用，以提供额外的上下文。

## 示例：`Create Supabase functions` 提示词

以下是一个生成高质量 PostgreSQL 函数的提示词，该函数遵循最佳实践：

```md title="supabase-create-functions.md"
---
name: Create Supabase functions
description: Guidelines for writing Supabase database functions
invokable: true
---

# Database: Create functions

You're a Supabase Postgres expert in writing database functions. Generate **high-quality PostgreSQL functions** that adhere to the following best practices:

## General Guidelines

1. **Default to `SECURITY INVOKER`:**

   - Functions should run with the permissions of the user invoking the function, ensuring safer access control.
   - Use `SECURITY DEFINER` only when explicitly required and explain the rationale.

2. **Set the `search_path` Configuration Parameter:**

   - Always set `search_path` to an empty string (`set search_path = '';`).
   - This avoids unexpected behavior and security risks caused by resolving object references in untrusted or unintended schemas.
   - Use fully qualified names (e.g., `schema_name.table_name`) for all database objects referenced within the function.

3. **Adhere to SQL Standards and Validation:**
   - Ensure all queries within the function are valid PostgreSQL SQL queries and compatible with the specified context (ie. Supabase).

...
```

<Info>
  您可以在 [这里](http://hub.continue.dev/supabase/create-functions) 阅读完整的
  `Create Supabase functions` 提示词
</Info>

如果您使用本地 `config.yaml`，可以像这样将其添加到您的配置中：

```md title="config.yaml"
...

prompts:

- uses: supabase/create-functions

...
```

如果您使用 Continue Mission Control，可以通过在 [这里](https://hub.continue.dev/supabase/create-functions) 选择 "Use Rule" 将其添加到您的配置中

要使用此提示词，您可以打开聊天/代理/编辑，键入 <kbd>/</kbd>，选择提示词，然后键入您想要添加的任何其他指令。

## 在 `cn (TUI 模式)` 中使用提示词

您可以运行此命令以使用 [Create Supabase functions](http://hub.continue.dev/supabase/create-functions) 提示词启动 [cn](../../guides/cli)。

```
cn --prompt supabase/create-functions "I need a function that checks for the health status
```
"
```
或者，您可以启动 [cn](../../guides/cli)，然后键入 <kbd>/</kbd> 手动调用提示词。

## 使用提示词通过 `cn (无头模式)` 启动持续 AI 工作流

您可以通过添加 `-p` 标志，使用带有 [cn](../../guides/cli) 的提示词启动持续 AI 工作流。

例如，假设您正在构建一个 SaaS 应用程序，并且必须为每个接受用户输入的新功能重复创建自定义 Supabase 验证函数。

这些函数要求您解释业务需求，实现复杂的跨表逻辑（如检查用户权限、层级限制和基于时间的限制），并对边缘情况做出判断。

每个函数都足够独特，无法模板化或脚本化。这就是启动持续 AI 工作流来帮助您入门的地方，这会非常有帮助。

以下是您可以在有新功能时运行的命令：

```
 cn -p --prompt supabase/create-functions "I need a function for the new feature on my current branch similar to my existing database functions"
```

<Info>您可以在 [这里](http://hub.continue.dev/supabase/create-functions) 查看完整的 `Create Supabase functions` 提示词</Info>

当您运行此工作流时，[cn](../../guides/cli) 将检查您当前的分支，探索新代码和现有代码，然后为您起草一个函数。

然后，您将能够在合并新功能之前审查实现并对其进行改进。
