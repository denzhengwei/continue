## 理解 Plan 模式

Plan 模式旨在帮助您在进行更改之前理解代码并构建计划。它位于聊天模式（无工具）和代理模式（所有工具）之间，提供了一个中间地带，您可以在其中进行探索和分析而没有风险。

### 关键区别：只读工具

虽然代理模式可以访问包括修改文件在内的所有工具，但 Plan 模式仅允许访问只读工具。这确保了：

- 不会创建、修改或删除任何文件
- 不会执行可能更改系统状态的命令
- 所有探索都是安全且非破坏性的
- 您可以自信地进行调查，而不会产生意外后果

## Plan 模式如何工作

当您选择 Plan 模式时：

1. Continue 发送一条特殊的系统消息，指示模型专注于理解和规划
2. 工具列表被过滤，仅包含只读工具
3. 模型可以使用这些工具来探索和分析您的代码库
4. 当您准备好实施更改时，您切换到代理模式

### Plan 模式中可用的工具

Plan 模式包括以下只读内置工具：

- **读取文件** (`read_file`)：读取项目中任何文件的内容
- **读取当前打开的文件** (`read_currently_open_file`)：读取当前打开文件的内容
- **列出目录** (`ls`)：列出文件和目录
- **Glob 搜索** (`glob_search`)：搜索匹配模式的文件
- **Grep 搜索** (`grep_search`)：使用正则表达式模式搜索文件内容
- **获取 URL 内容** (`fetch_url_content`)：从网页 URL 检索内容
- **搜索网页** (`search_web`)：执行网页搜索以获取更多上下文
- **查看差异** (`view_diff`)：查看当前的 git 差异
- **查看仓库地图** (`view_repo_map`)：获取仓库结构的概览
- **查看子目录** (`view_subdirectory`)：获取特定目录的详细视图
- **代码库工具** (`codebase_tool`)：高级代码库分析功能

### MCP 工具支持

除了内置的只读工具外，Plan 模式还支持所有 MCP（模型上下文协议）工具。这允许与提供额外上下文或分析功能的外部服务集成，而无需修改您的本地环境。

<Info>
  虽然 Plan 模式将内置工具限制为只读操作，但 Continue 不会过滤 MCP 工具。一些 MCP 工具可能具有写入功能，可能会修改您的系统或外部服务。在 Plan 模式中使用 MCP 工具之前，请始终验证它们可以执行哪些操作。
</Info>

## 规划工作流

典型的 Plan 模式工作流遵循以下步骤：

1. **探索**：使用只读工具了解当前状态
2. **分析**：确定需要更改的内容和潜在影响
3. **规划**：制定详细的实施计划
4. **验证**：审查计划并确保它满足所有要求
5. **执行**：切换到代理模式实施计划

### 示例：规划重构

```
用户：帮助我规划一个重构，将身份验证逻辑提取到一个单独的模块中

Plan 模式：
1. 读取相关文件以了解当前结构
2. 分析依赖关系和使用模式
3. 识别所有需要更新的地方
4. 创建一个逐步的重构计划
5. 建议："切换到代理模式来实施这个计划"
```

## 系统消息和行为

Plan 模式使用专门的系统消息，该消息：

- 指示模型专注于理解和规划
- 强调仅使用只读工具
- 提醒模型建议切换到代理模式进行实施
- 鼓励在建议更改之前进行彻底分析

<Info>
  系统消息可以按模型自定义。您可以 [直接在代码中查看](https://github.com/continuedev/continue/blob/main/core/llm/defaultSystemMessages.ts)。
</Info>

## 何时使用 Plan 模式与其他模式

### 何时使用 Plan 模式：

- 探索不熟悉的代码库
- 规划复杂的重构或功能
- 调试和理解问题
- 审查代码架构
- 创建实施策略

### 何时使用聊天模式：

- 进行不需要文件访问的讨论
- 询问一般编程问题
- 在不探索代码的情况下获取解释

### 何时使用代理模式：

- 准备好实施更改
- 需要创建或修改文件
- 想要运行命令或测试
- 实施在 Plan 模式中制定的计划
